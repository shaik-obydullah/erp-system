Module 04 — Inventory & Stock Management

Module: Inventory & Stock Management (Inventory)
Category: Operations
Purpose: Tracks every sellable unit — product stock entries, warehouses, service inventory items, and corrections — while feeding real-time availability to the POS, storefront, and reports.

Stock is the heartbeat of the ERP. Every sale decrements stock inside a database transaction, and every restock/return/adjustment increments it. Accuracy here guarantees accuracy everywhere else — financials, forecasts, and fulfillment.

1. Overview

The inventory module manages four entities:

  • Inventory — non-product service items (e.g. installation, support) with a status lifecycle.
  • Stocks — purchasable units linked to a product, with batch/lot tracking, cost, and sale price.
  • Warehouses — physical storage locations with capacity and contact data.
  • Stock Adjustments — corrections with a reason (correction/damage/return).

3. Key Models & Relationships

  • Stock (app/Models/Stock.php) — product() belongs-to; warehouse() belongs-to. Casts: buy_price, sale_price decimal(2), quantity integer.
  • Product — stocks() has-many; computed stock_quantity = sum of quantity on active stocks.
  • Warehouse — stocks() has-many via fk_warehouses_id.
  • Inventory — standalone service items, optional link to stocks via fk_inventory_id.
  • StockAdjustment — audit-style record of corrections referencing a stock and optional warehouse.

4. Stock Entry Lifecycle

  1. Create — a stock record is created (admin panel or API) with product, warehouse, batch/lot, quantity, buy price, sale price.
  2. Sell — POS/API checkout decrements quantity via Stock::decrement() inside a DB::transaction() (exactly once).
  3. Return — approved sale returns restock by incrementing quantity.
  4. Adjust — StockAdjustment records corrections with an auditable reason.
  5. Delete sale — restoring stock when a sale is deleted (API deleteSale increments each detail's stock back).

7. Stock Reporting

ReportController::stock (GET /reports/stock, permission:dashboard.view):

  • Total stock value — sum of quantity × buy_price on active stocks.
  • Low-stock items — active stocks with quantity < 10, ascending.
  • Stock by category — quantity and value grouped by category (bar chart).
  • Stock list — full listing ordered by stock value descending.

Dashboard also exposes total stock value (quantity × buy_price) and the API POST /report returns stock_value for the POS report screen.

8. Inventory Insights (AI)

POST /api/v1/ai/inventory-insights sends active stock data (product, batch, quantity, buy/sale price, computed margin) to Ollama, which returns prioritized recommendations — restock items, overstocked items, reorder quantities, and risk signals. When Ollama is down the endpoint returns 500 with an error JSON; the React UI must degrade gracefully.

9. Flash Sales

flash_sales table links a stock (fk_stock_id) to a time-limited percentage discount within start_date/end_date — promotional pricing surface for the storefront.

11. Conventions & Gotchas

  • Stock moves only inside DB transactions. Sale checkout, sale deletion, and return approval all wrap stock changes in DB::beginTransaction() / DB::commit() with rollback on failure.
  • Exactly-once decrement — verify a stock line is never decremented twice; sale deletion restores it once.
  • POS cart guards quantity — addToCart and checkout reject quantities exceeding available stock.
  • Thresholds (e.g. low-stock < 10) are configurable via system settings.
