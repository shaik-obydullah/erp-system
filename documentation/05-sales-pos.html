Module 05 — Sales & Point of Sale (POS)

Module: Sales & POS (Sales)
Category: Core Revenue
Purpose: Captures revenue through two front-ends — an in-admin Blade POS and a standalone React 19 terminal — and manages orders, invoices, dues, and returns with full accounting integrity.

The POS checkout is the canonical transactional flow of the ERP. A single sale atomically writes Sale + SaleDetails + stock decrement + Transaction + Income + Cashbook inside one database transaction. Every money-moving or stock-moving operation in the system follows this same pattern.

1. Overview

The sales module covers:

  • Admin POS — Blade-based terminal with a persistent per-admin cart (AJAX add/remove, live recalculation, one-click checkout).
  • React POS — standalone Vite app consuming the Sanctum REST API; category browsing, tap-to-add, localStorage persistence, invoice PDF via jsPDF.
  • Sales ledger — order listing, detail view, printable invoice, due collection.
  • Sale returns — request → approve/reject workflow that restocks items and writes refund accounting.

3. Key Models & Relationships

  • Sale (app/Models/Sale.php) — details() / saleItems() has-many; transaction() has-one (saleIncome type); customer() belongs-to. Money columns cast to decimal(2).
  • SaleDetail — belongs-to Sale and Stock; denormalizes stock_name, size, color at time of sale.
  • SaleReturn — belongs-to sale() and stock().
  • Cart / CartDetail — admin-scoped (or user-scoped) persistent cart with totals recomputed by PosController::recalculateCart.

4. Sale Status Lifecycle

Status enum: orderPlaced → processing → shipment → completed — with canceled as a terminal state. POS checkouts are created directly as completed; ecommerce orders start at orderPlaced.

5. Admin POS (Blade)

PosController — routes GET /pos (permission:pos.view), POST /pos/cart/add · cart/remove · checkout (permission:pos.save):

  1. index() — first-or-creates a cart for the logged-in admin; loads cart details with stock/product; lists active in-stock items; reads currency, VAT, tax rates and active customers.
  2. addToCart() — validates stock exists and quantity available; upserts a cart detail (merging quantities) and recalculates totals.
  3. removeFromCart() — deletes a detail and recalculates.
  4. checkout() — transactional:
    1. Computes net, discount, shipping, grand total, paid, and due (max(0, grand - paid)), and total buy price.
    2. Creates Sale (type POS, status completed) + SaleDetails.
    3. Decrements each stock's quantity (floored at 0).
    4. Writes Transaction (saleIncome), Income record, and Cashbook entries (payment received + receivable if due).
    5. Clears the cart, commits, logs activity, redirects to invoice.

6.1 API Checkout Flow (ApiController::saveSale)

  1. Validates items (stock exists, quantity ≥ 1), subtotal, VAT, tax, discount, total.
  2. Generates INV-XXXXXXXX-time() invoice id.
  3. Inside DB::beginTransaction():
    • Creates Sale (POS, completed, paid = total, due = 0).
    • For each item: creates SaleDetail (snapshot name + stock qty) and decrements stock.
    • Creates Transaction (saleIncome), Income, Cashbook (in = total).
    • Logs ActivityLogger::created('Sale', $sale).
  4. Commits; returns sale + invoice id. On exception, rolls back and returns 500.

8. Sale Returns

SaleReturnController — routes under sale-returns (permissions sales.*):

  1. store — creates a request with status pending.
  2. approve — transactional effect:
    • Sets status approved.
    • Increments the referenced stock's quantity (restock).
    • Writes Transaction (miscExpense) + Cashbook (out = refund).
    • Reduces the sale's paid_amount and grand_total.
  3. reject — sets status rejected.

11. Financial Integrity Conventions

  • Always wrap checkout in DB::transaction(). Verify cashbook/transaction rows are written and stock is decremented exactly once.
  • Invoice IDs: admin POS uses INV-{uniqid}; API uses INV-{random}-{time}. Both unique-indexed.
  • Due money flows through saleDue transactions and receivable cashbook lines — never mutate only the sale row.
